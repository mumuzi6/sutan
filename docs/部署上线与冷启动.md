## 1. 部署架构

```
用户浏览器
    ↓ HTTPS
宝塔 Nginx (443/80)
    ├─ 静态文件 → /www/wwwroot/sutan/dist/   (Vue3 build 产物)
    └─ /api/* 反代 → http://127.0.0.1:8080   (Spring Boot)
                        ├─ PostgreSQL+pgvector (Docker, 5432)
                        ├─ DeepSeek API (外网)
                        ├─ SiliconFlow API (外网, embedding)
                        └─ Langfuse Cloud (外网, OTLP trace)
```

**内存预算（4G）**：
| 组件 | 预估 |
|---|---|
| OS + 宝塔 | ~0.5G |
| PostgreSQL | ~0.5G (shared_buffers=128MB) |
| Spring Boot (JVM -Xmx512m) | ~0.8G |
| Nginx | ~0.1G |
| 余量 | ~2G |
| **合计** | **~2G / 4G** ✅ |

## 4. 数据库部署

### 4.1 docker-compose.yml（服务器版）
在 `/opt/sutan/docker-compose.yml`：
```yaml
services:
  postgres:
    image: pgvector/pgvector:pg16
    container_name: sutan-postgres
    restart: always
    environment:
      POSTGRES_USER: sutan
      POSTGRES_PASSWORD: ${DB_PASSWORD:-改个强密码}
      POSTGRES_DB: sutan
    ports:
      - "127.0.0.1:5432:5432"   # 仅本地访问
    volumes:
      - pgdata:/var/lib/postgresql/data
    command: >
      postgres -c shared_buffers=128MB -c max_connections=50

volumes:
  pgdata:
```

### 4.2 启动
```bash
cd /opt/sutan && docker compose up -d postgres
docker exec sutan-postgres psql -U sutan -c "create extension if not exists vector;"
```

## 5. 后端部署

### 5.1 方式一：服务器上构建（推荐，2核够用）
```bash
# 上传代码到 /opt/sutan/repo
cd /opt/sutan/repo
docker compose build backend
```

### 5.2 docker-compose 加 backend 服务
```yaml
  backend:
    build:
      context: ./repo
      dockerfile: sutan-backend/Dockerfile
    container_name: sutan-backend
    restart: always
    environment:
      DB_HOST: postgres
      DB_PORT: 5432
      DB_NAME: sutan
      DB_USER: sutan
      DB_PASSWORD: ${DB_PASSWORD:-改个强密码}
      DEEPSEEK_API_KEY: ${DEEPSEEK_API_KEY}
      EMBEDDING_API_KEY: ${EMBEDDING_API_KEY}
      LANGFUSE_AUTH: ${LANGFUSE_AUTH}
    ports:
      - "127.0.0.1:8080:8080"
    depends_on:
      postgres:
        condition: service_healthy
    # JVM 内存限制
    mem_limit: 1g
    java_opts: "-Xmx512m -Xms256m"
```

### 5.3 环境变量
在 `/opt/sutan/.env`（不要提交到 Git）：
```env
DB_PASSWORD=你的强密码
DEEPSEEK_API_KEY=sk-你的deepseek密钥
EMBEDDING_API_KEY=sk-你的siliconflow密钥
LANGFUSE_AUTH=base64编码的(public_key:secret_key)
```
> Langfuse AUTH 生成方式：`echo -n "pk-xxx:sk-xxx" | base64`

### 5.4 JVM 调优
在 Dockerfile ENTRYPOINT 加：
```dockerfile
ENTRYPOINT ["java", "-Xmx512m", "-Xms256m", "-jar", "app.jar"]
```

### 5.5 启动
```bash
cd /opt/sutan && docker compose up -d
docker compose logs -f backend   # 看启动日志
```

## 7. Nginx 配置（宝塔）

### 7.1 宝塔添加站点
- 域名：`sutan.你的域名.com`
- 根目录：`/www/wwwroot/sutan/dist`
- PHP：纯静态

### 7.2 SSL 证书
- 宝塔 → 站点 → SSL → Let's Encrypt → 申请（免费）
- 开启强制 HTTPS

### 7.3 Nginx 配置（站点设置 → 配置文件）
```nginx
server {
    listen 443 ssl;
    server_name sutan.你的域名.com;

    ssl_certificate     /www/server/ssl/sutan/fullchain.pem;
    ssl_certificate_key /www/server/ssl/sutan/privkey.pem;

    # 前端静态文件
    root /www/wwwroot/sutan/dist;
    index index.html;

    # Vue Router history 模式
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反代到后端
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 支持（Agent 流式）
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 120s;
    }
}

# HTTP 强制跳转 HTTPS
server {
    listen 80;
    server_name sutan.你的域名.com;
    return 301 https://$host$request_uri;
}
```

## 11. 简历写法建议

### 项目描述模板
> **诉探 Sutan · 法考 Agent 导师** | Spring Boot + Spring AI + DeepSeek + pgvector + Vue3
>
> - 面向法考二战/主观题党，自研 ReAct 编排内核（非调包），实现会查法条、会模拟阅卷的 Agent 导师
> - **手写 ReAct 编排**：LLM 输出 Thought/Action/ActionInput 协议文本，自解析自调度工具（查法条/案例/阅卷），maxSteps=6 防死循环；不依赖 Function Calling，显原理
> - **法条级强制溯源**：RAG 检索 + pgvector 向量召回 + bge-reranker，每个答案附法条出处+案号+真题年份；未溯源自动标记（幻觉规避）
> - **模拟阅卷人**：DeepSeek 三层标准批改（扣分排查→采分点核对→得分核定），结构化报告含命中/缺失/法条/逻辑/改进建议
> - **真实上线运营**：网页零门槛，Docker 部署，Langfuse 可观测；上线 X 周获 N 注册、M 次对话、K 次批改（填真实数据）
> - **竞品分析与差异化**：调研 Pass100/Kukukao/觉晓等，定位"Agent+溯源+个人知识库"缝隙，非教程 clone

### 面试可深挖清单
- ReAct 协议为什么用文本解析而非 Function Calling？（原理理解 + 可控性）
- 溯源怎么保证？（RAG metadata + citations 收集 + groundCheck）
- RAG 召回质量怎么优化？（chunking 策略 + rerank + 混合检索对比数字）
- 阅卷人 prompt 怎么设计？（三层标准 + JSON 结构化 + 容错）
- 为什么不用 LangChain4j？（单一框架 + 自研核心 = 显原理 + 少依赖）
- 多模型共存怎么解决 bean 冲突？（spring.ai.model.chat/embedding 顶层开关）
