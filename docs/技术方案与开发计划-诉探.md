## 1. 产品定位与差异化（复述对齐）

- **MVP 切口**：法条级可溯源 Agent 答疑 + 模拟阅卷人批改（2 周出可上线版本，先验证真实用户）。
- **v2 壁垒**：用户上传个人资料（笔记/讲义/错题）构建专属知识库，Agent 基于"官方法条库 + 你的资料"答疑+出题。
- **三大护城河**（同时服务求职+商业）：
  1. **定位重构**：不是"AI 问答"，是"会查法条、会模拟阅卷的 Agent 导师"——Agentic 多步推理是核心体验。
  2. **法条级强制溯源**：每个答案附法条出处+案号+真题年份，降低幻觉；既是 liability 兜底，也是"RAG grounding/幻觉规避"的顶级面试亮点。
  3. **可构建个人知识库（v2）**：Lawbot 思路、大陆缺位，黏性远高于纯问答。
- **轻量网页 + 零门槛 + 分享裂变**：不下载、不卖课，绕开机构"先买课"转化漏斗。

## 2. 技术栈（已参考鱼皮/JavaGuide 对比优化）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | **Spring Boot 3.5.x + Java 21** | LTS，与鱼皮对齐稳定 GA（避免 Spring Boot 4 预览版） |
| Agent 框架 | **Spring AI 1.0.0 GA（仅此一个 AI 框架）+ 全自研 ReAct 编排层** | **不引入 LangChain4j**：少一个依赖，突出"懂原理非调包"差异化 |
| 大模型 | **DeepSeek**（`spring-ai-starter-model-deepseek`，Spring AI 原生支持） | 用户确认；推理强、性价比高 |
| Embedding | **DashScope text-embedding-v2 或 BGE-M3**（本地/SiliconFlow） | 与 chat 模型解耦，可独立切换 |
| Rerank | **bge-reranker-v2-m3**（SiliconFlow 免费额度 / 本地） | **差异化强化**：召回质量，鱼皮未强调 |
| 向量库 | **pgvector（PostgreSQL 扩展）** | 法条/案例/真题 embedding + 混合检索 |
| 关系库 | **PostgreSQL**（共用实例） | 用户/会话/统计/内容 |
| 对话记忆 | **Spring AI ChatMemory + JDBC/PG 持久化** | **生产级**，区别于鱼皮的 FileBasedChatMemory(Kryo 落盘) |
| 前端 | **Vue3 + Vite + TS + Element Plus，SSE 流式** | 网页优先，零安装 |
| API 文档 | **Knife4j** | 标配 |
| 可观测 | **Langfuse** | Trace/成本/质量，面试亮点 |
| 部署 | **Docker + 学生机/Serverless** | 健康检查 + CI 分步提交 |
| 辅助 | **Redis**（限流/缓存）、Hutool、**MinIO**（v2 文件） | 成本控制 |

### 2.1 与鱼皮 `yu-ai-agent` / JavaGuide 对比（趋同 vs 差异）

| 维度 | 鱼皮 yu-ai-agent | JavaGuide 推荐 | **诉探（本方案）** | 选择理由 |
|---|---|---|---|---|
| AI 框架 | Spring AI + LangChain4j 双框架 | Spring AI/Alibaba/LangChain4j 等对比 | **仅 Spring AI 1.0 + 全自研编排** | 少依赖、突出自研、讲故事 |
| 大模型 | DashScope(qwen) / Ollama | — | **DeepSeek** | 确认；Spring AI 原生支持 |
| Embedding | Sentence Transformers/OpenAI | — | DashScope / BGE-M3 | 与 chat 解耦 |
| Rerank | 未强调 | — | **bge-reranker（强化）** | 召回质量差异化 |
| 对话记忆 | FileBasedChatMemory(Kryo 落盘) | — | **JDBC/PG 持久化** | 生产级 |
| **领域** | 恋爱大师 | 面试辅助 | **法考/法律** | 真实用户 + 你的背景 |
| **溯源** | 未强调 | — | **法条级强制溯源** | liability + 幻觉规避亮点 |
| **真实用户** | 无 | 无 | **有 + admin 运营数据** | 简历核武器 |
| **个人知识库** | 无 | 无 | **v2 上** | 黏性壁垒 |
| MCP | 有（图片搜索） | 协议支持 | 有（法条/案例/阅卷） | 同栈、不同域 |
| 前端 | Vue3 SSE | — | Vue3 SSE | 趋同（合理） |

> **关键结论**：**技术栈趋同是必然**（Spring 生态主流就是这套 Spring AI + pgvector + Vue3 + MCP），所以**照搬栈没问题**——但**绝不能照搬领域和定位**。差异不在"用了什么框架"，而在"领域垂直 + 自研编排 + 强制溯源 + 真实用户 + 个人知识库"。这正是我们不引入 LangChain4j 的原因：避免"和鱼皮一模一样的双框架栈"，转而用"单一框架 + 更深自研"的叙事，更干净、更显原理功底。

## 5. Agent 编排设计（手写 ReAct，核心亮点）

伪代码骨架：

```
loop (max_steps=6):
    thought = llm(系统提示 + 记忆 + 工具描述 + 观察)
    if thought.action == "answer":
        return ground(answer, 收集到的 citations)   # 强制溯源
    tool = registry.get(thought.action)
    observation = tool.execute(thought.args)         # 查法条/案例/真题/阅卷
    memory.append(observation); citations.merge(tool.citations)
reflect(): 校验答案是否覆盖 citations；缺则补 tool 调用
```

- **工具集**：`search_law`（法条向量+关键词混合）、`search_case`（类案）、`search_question`（真题/采分点）、`grade_answer`（模拟阅卷人，给采分点/法条引用/逻辑漏洞）、`web_search`（兜底）。
- **溯源机制**：每个工具返回结构化 citation（法规名+条+款/案号/年份）；最终答案只引用被检索到的来源，杜绝编造。
- **模拟阅卷人**：`grade_answer` 输入用户作答→调用 RAG 取采分点→输出"命中/缺失/法条引用错误/逻辑漏洞"+ 改进建议（对标真实阅卷三层标准）。

## 6. RAG 设计（面试高频覆盖）

- **语料**：公开法条（人大/司法部）、指导性案例、开源/自生成真题解析（规避版权）。
- **切片**：法条按"条/款"切；案例按"争议焦点+裁判要点"；题目按"考点"切。
- **检索**：向量召回 + 关键词(BM25) 混合 → **rerank**（交叉编码器/规则）→ Top-K。
- **优化故事**（准备对比数字）：chunking 策略、rerank 前后召回@5、幻觉率下降。
- **溯源**：返回结果带出处，前端可点击跳转原文。
